# Problems actually hit

These are problems met while building a bird model (two versions) and a quadruped cat model. Each entry is written as symptom -> cause -> fix.

## Image measurement

- **Fill colors bleed in from the wrong place** -> `np.roll` wraps around the image edge, so the beak color at the right edge went into the left background -> do the neighbor average with a shift that does not wrap (`shift`). Every fill in `measure_views.py` uses it.
- **Legs and toes stick to the underside of the body** -> the opening that erases legs (erode -> dilate) leaves the clump where two toes overlap, and the row of toes is wide horizontally, so it also passed the rule "horizontal run of 4 cm or more" -> erase everything below the toe height (`toeCm` 1.3), keep only horizontal runs of 4 cm or more up to `cutCm` (3.0) above that, and narrow the f range to erase to the area around the legs (`sideRangeCm`) so the tail tip is not erased. Check with `debug_side_legs.png`.
- **Front eye height came out as 7.6 cm** -> the feet (pink) got mixed into the orange detection -> search only above `minHeightCm`.
- **A dark band on the flank where the wing sits** -> the source of the diffusion fill was the underside of the belly, which was darkly lit in the sheet -> mix 60% with the sheet's body color (`keyColour` x 0.9). Remove the tail under the wing feathers (dark) from the source (`excludePx`).

## Shape and parts

- **Pupil is an angular square** -> the poles of a UV sphere are on Z, and picking the pupil faces by an angle around the normal cut the face boundaries at a slant -> rotate the pole to the outward normal when building the sphere.
- **A mesh with the same name becomes `.001`** -> the mesh from before deletion still held the name -> delete the old mesh, then assign the name again (the glb node name changes too).
- **The folded-wing outline breaks into stair steps** -> picking shell faces by face center is as ragged as the face size -> split the edges by signed distance to the outline (`bmesh.utils.edge_split`, UVs are interpolated too), divide the faces, and delete the outer faces. Cutting by alpha prevents using JPEG (see below).
- **The back of the spread-wing root looks like it floats above the back** -> a standing body has its axis tilted up about 23 degrees, but the wing was attached horizontally -> align the wing coordinates to the body axis with a pitch of 15 degrees (`spread.frame.pitchDeg`). In the flight pose the body lies down and the wing becomes level.

## Baking and export

- **The projected texture looks angular** -> it was baked at subdivision level 1 -> bake at render level 2 (`loft.subdiv`) and export at level 1 (`export.subdiv`).
- **The glb was 8.9 MB** -> the glTF exporter writes textures that need alpha as PNG even in JPEG mode, and a packed PNG has its bytes copied as is (a 2048 RGBA photo PNG is 5.3 MB) -> cut the folded wing by geometry and use an opaque JPEG; for the spread-wing PNG, replace the color outside the alpha with a flat color (keeping only a 6 px margin) to optimize, and halve the size of the underside. Palette quantization (256 colors) is not used because the feather gradation breaks into steps.
- **Alpha is not exported as MASK** -> the material alpha must pass through a Math Round node for the glTF exporter to write `alphaMode: MASK` (0.5).
- **The order of eye triangles in the exported glb differs from build to build** -> the index order of the eye primitive, which is split into two materials, changes with each export (fixing `PYTHONHASHSEED` does not change it). The vertex and triangle sets and the JSON are the same. For the cat's eye, which has three materials, even the buffer view order changes, so the JSON and the file size (by a few dozen bytes) differ too, but the triangle set per mesh and material is the same -> compare with `inspect_model.py` and `compare_models.py`. Do not compare by glb file hash.
- **A rigged .blend opens in the flight pose** -> exporting the glb in NLA track mode leaves the last sampled action pose on the pose bones, and the tracks are off so nothing reverts it -> after exporting, return the pose to the rest pose and save. `inspect_model.py` reads the armature with it set to REST.
- **Packed images cannot be read in the dump** -> in background mode a packed image is read the first time it is used -> read `img.pixels[0]` first, and save by changing only the path instead of `copy()`.

## Quadruped (cat model)

- **A cross-shaped thin membrane and holes between the legs** -> applying the OpenVDB `SDF Grid Fillet` to the body and leg SDF union tried to fill the concave gap where the upper parts of the left and right front legs face each other 1.8 cm apart, and a membrane formed (widening the band width changed nothing) -> do not fillet in the SDF. Give weights only to vertices that are within `filletCm` of both the body loft surface and the leg surface, and smooth them on the mesh with Smooth (`sdf_union.py`). Between the two legs only one leg is close, so it is left alone.
- **Building twice from the same spec gave body vertex counts differing by 2** -> OpenVDB `SDF Grid Fillet` and `SDF Grid Laplacian` give slightly different results on each run (the same even with `-t 1`). The closing that turns a voxel mesh back into an SDF also moved some vertices by 1e-7 m because several faces are at the same distance -> use only mesh -> SDF (per part), union, SDF -> mesh (threshold 0), and the Smooth modifier. This combination is identical down to the bytes over repeated runs. When changing it, run it several times in the same session and compare a hash of the vertex coordinates.
- **A triangle cap (`maxTris`) was silently in effect** -> noticed because the reported triangle count was near the cap every time (31980, 32000). The original mesh at a 0.3 cm voxel had 60,000 -> set the density by voxel size (about 30,000 at 0.45 cm, uniform quads) and do not use decimation. With decimation the triangles become uneven, and the density drops where the back and flanks bend during a gallop.
- **The upper body is angular and too wide (red in the front and back overlay)** -> a superellipse cross section is symmetric top to bottom, but the cat body narrows sharply above z 18 cm (back view +-5.4 -> +-3.4 at z 22) -> clip the cross section at each height to the wider width of the front and back views (`loft.clampViews`). With only the front, the head hides the shoulders and the back gets clipped to the head width.
- **The eyeball and the painted eye show separately (four eyes)** -> the muzzle made from the silhouette is as wide as the whisker pad even at eye height, so at the front view's eye position (x 1.54 cm) the surface was 1.7 cm ahead. No silhouette contains this information -> make the nose bridge with `loft.upperTaper`, which narrows only the upper part of the cross sections in front of the eyes, and place the eyeball with a ray shot along the gaze direction (`gazeDeg`). If the views disagree on eye height (front 23.8, side 23.2), erase the leftover painted eye with `texture.bodyFillPx`.
- **Pink smudge on the temple** -> in the side picture the inside of the ear (pink) was drawn in front of the head, so it got projected onto the side of the head -> bake the body from a copy with the ear area filled in (`tex_side_body.png`) and bake the ears separately from the original views (one 512 px ear texture).
- **"empty silhouette" at the tail tip after the opening** -> the 1 px tail-tip column was erased by the whisker-removal opening -> measure an empty end column a few px further inside (`nonempty_column`).
- **Whiskers, paws, and ears mixed into the top-view width** -> the top silhouette had whiskers (thin lines), paws sticking out 0.5 cm beyond the body, and ears sticking out beyond the head -> erase thin things with `silhouette.openCm` and cut out paws and ears with `silhouette.cutsPx` polygons. The texture uses the uncut silhouette.
- **Front and back views draw the hind-leg spacing differently** -> the front view has the outside of the hind paws at +-5.9 cm and the back view at +-4.3 cm (the generated images differ from each other) -> read the hind legs from the back view and the front legs from the front view, and report the remaining difference in the `overlay_views.py` overlay as a view mismatch. It cannot be matched to both views.
- **The vertex group for the fillet stayed on the body mesh** -> the vertex group name stayed attached to the mesh even after smoothing on the mesh, and it nearly got mixed into the rigging step -> delete the vertex group after smoothing.
- **A long body is off to one side in the inspect render** -> the camera center was the average of the mesh box corners, so it was pulled toward the head-side parts (eyes, ears) -> center it on the middle of the whole bounding box. Compare renders only between dumps made with the same script.

## Runtime environment

- **The Blender MCP cannot run this pipeline** -> the MCP safe mode blocks numpy, `os`, `open`, `exec`, `setattr` with a computed name, calling a function held in a variable, and opening other .blend files -> run every build with `blender -b --factory-startup -P`. Use the MCP only to look at the result in the user's Blender.
- **`.blend1` is created when overwriting a save** -> save with `preferences.filepaths.save_version = 0`.
- **A cleanup command like `rm -rf $DIR/$x` is blocked** -> deleting a variable path trips the safety check -> build to a new folder name or use an absolute path.
